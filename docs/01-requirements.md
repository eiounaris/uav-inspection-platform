# 无人机集群巡检数据共享与证据溯源平台——需求说明

| 项目 | 内容 |
| --- | --- |
| 目标版本 | MVP（首版可演示版本） |
| 更新日期 | 2026-10-19 |
| 应用场景 | 园区设施巡检 |
| 参与机构 | 委托方 OrgA、无人机运营商 OrgB |
| 核心定位 | Java 后端完成业务处理，Fabric 提供文件摘要存证 |

## 1. 项目目标

委托方发布巡检任务，运营商安排多架无人机分区执行。平台统一管理采集资料的上传、版本、人工复核和授权共享，并通过 Fabric 核验文件内容是否与登记版本一致。

项目需要完成一次可演示的业务闭环，并体现任务管理、可靠上传、资源权限、幂等处理、异步任务和异常恢复等 Java 后端能力。

首版使用 3～5 台模拟无人机，两个机构分别使用独立的 Fabric 应用身份。用户登录身份与机构的 Fabric 应用身份分开管理。

## 2. 范围与边界

### 2.1 首版范围

- 用户登录、角色权限和机构数据隔离。
- 总任务及子任务管理、无人机分配、心跳和进度汇总。
- 文件上传、分片续传、服务端摘要计算和不可覆盖的版本管理。
- 人工提交异常、复核通过、退回补充资料。
- 资料共享申请、审批、授权到期、撤销和受控下载。
- 文件摘要登记、存证状态查询和文件完整性核验。
- 重复请求、重复消息、存证超时及服务重启后的恢复处理。
- 关键操作记录、部署说明和核心场景验证记录。

图片和 PDF 报告为必测资料；视频按普通文件保存和下载，不要求转码、流媒体播放或内容识别。文件类型、大小、分片大小及上传会话有效期应可配置。

### 2.2 Fabric 范围

采用两个业务组织、一个通道、一份链码，链码仅提供两个业务操作：

```text
RegisterEvidence(证据编号, 版本, 文件摘要)
QueryEvidence(证据编号, 版本)
```

链码从调用身份识别提交机构并校验权限：首版仅允许运营商 OrgB 的应用身份登记摘要，委托方 OrgA 与运营商 OrgB 的应用身份均可查询。保存证据编号、版本、SHA-256 摘要及必要的提交信息。交易提交与有效性确认属于接入流程，不增加链上业务模块。

原始文件存放在对象存储；任务、设备、文件关联、复核、共享权限和业务操作记录保存在业务数据库。人工复核和共享授权由 Java 后端执行。

### 2.3 首版不包含

真实飞控、编队控制、路径规划、自动缺陷识别、结算支付、私有数据集合、多通道、链上授权和复杂背书策略。首版采用模块化单体，不要求微服务拆分或生产级链网络部署。

## 3. 用户角色与访问规则

| 角色 | 主要权限 | 访问范围 |
| --- | --- | --- |
| 委托方任务管理员 | 创建任务、维护巡检要求、分配运营商、确认任务完成 | 本机构负责的任务 |
| 委托方复核人员 | 查看待复核资料、确认异常、通过或退回版本 | 被分配的任务 |
| 委托方资料审批人员 | 审批共享、设定有效期、撤销授权 | 有管理权限的任务资料 |
| 运营商任务管理员 | 管理本机构设备、分配无人机、汇总执行结果 | 委托方交付给本机构的任务 |
| 运营商操作人员 | 上报执行进度、上传资料、提交异常和补充版本 | 被分配的任务及子任务 |
| 获授权用户 | 查看和下载指定版本 | 授权明确覆盖的版本与有效期 |

一个账号可以具备多个角色。机构管理员不自动拥有另一机构的资料权限；用户也不因属于某机构就获得该机构全部任务的访问权。

首版约定委托方为任务成果的资料管理方，运营商为提交方；共享审批由委托方执行。机构和用户归属以认证结果为准，不采信请求中自行填写的机构身份。

列表、详情、预览、下载、核验接口均须校验资源权限。设备只能向所属运营商获准执行的任务上报数据。

## 4. 核心业务流程

1. 委托方创建任务，明确巡检范围和必交资料要求，并指定运营商。
2. 运营商将任务拆分或细化为子任务，分配给多架无人机；委托方可以查看分配结果。
3. 无人机模拟器上报心跳和进度，操作人员或模拟器上传关联资料。
4. 平台完成文件校验，创建固定文件版本，并计算 SHA-256 摘要。
5. 平台异步登记摘要，展示存证进度，确认交易有效后标记为已存证。
6. 运营商提交异常与待复核资料，复核人员通过或退回；补充、更正资料创建新版本。
7. 必交资料满足要求后，委托方确认任务完成。
8. 其他已注册用户申请访问指定成果版本，由有权限的委托方人员审批。
9. 获授权用户下载文件或进行核验，系统记录访问及核验结果。

文件入库、人工复核、链上存证是不同环节。任务内有权限的人员可查看待复核资料；面向额外共享申请的正式成果，必须同时满足“复核通过”和“存证已确认”。

## 5. 功能需求

| 编号 | 功能 | 必须满足的行为 |
| --- | --- | --- |
| FR-01 | 用户与机构 | 支持两机构账号登录、角色分配、任务及资源级访问校验；未授权请求不得返回资料或下载凭证 |
| FR-02 | 多机任务 | 一个任务可拆成多个子任务并分配不同设备；展示执行进度、已提交资料和缺失项；设备离线不直接判定任务完成或失败 |
| FR-03 | 设备上报 | 记录设备归属、最近心跳和在线状态；可配置离线阈值；重复上报不得重复累计任务成果 |
| FR-04 | 文件上传与版本 | 支持分片上传、进度查询、断线续传、服务端完整文件摘要计算；重复完成请求只形成一个正式版本 |
| FR-05 | 异常与复核 | 异常和复核关联具体文件版本；支持通过、退回及填写原因；原始文件和历史复核记录保留 |
| FR-06 | 共享与下载 | 申请与审批绑定指定版本和有效期；支持拒绝、到期和撤销；对象存储不公开访问 |
| FR-07 | 摘要存证与核验 | 完成两个链码业务操作；查询存证状态；对有权访问的指定版本执行摘要比较并返回明确结果 |
| FR-08 | 异常恢复与审计 | 存证任务可重试、查询和恢复；重复执行不产生重复业务结果；记录关键操作、失败原因与处理结果 |

### 5.1 多机执行规则

- 任务至少包含一个子任务；每个子任务应明确执行设备并配置至少一项必交资料要求，不能仅凭心跳或上报进度达到 100% 判定成果合格。
- 支持人工调整设备分配；记录执行批次和调整历史，旧批次迟到的数据不得覆盖新批次的正式成果。首版仅处理人工调整，不实现自动重调度。
- 分别展示执行情况与成果验收情况；每项必交资料以当前执行批次最新提交的固定文件版本参与验收，新版未通过复核或未确认存证时，该资料项不满足完成条件。
- 只有全部子任务的必交资料均满足要求后，委托方才可确认任务完成。已完成任务不再接受新的正式成果版本，历史文件仍可按权限下载和核验。

### 5.2 文件与版本规则

- 文件版本必须关联任务、子任务、执行批次、提交设备或操作人员，以及提交机构。
- 正式版本生成后不得覆盖文件内容；更正或补充资料创建新版本，旧版本仍可追溯。
- 复核结论和共享授权绑定具体版本，新版本不自动继承旧版本的通过结论或授权；旧版本的既有授权仍按原有效期及撤销状态执行。
- 核验副本不得覆盖正式文件，也不得自动登记为新版本。
- 不符合配置限制的上传应返回明确原因；不完整上传不得作为正式证据。

### 5.3 共享规则

- 申请人必须是两个机构内的已注册用户，审批指定版本及访问期限；不扩展第三机构接入。
- 同机构内未参与任务的用户也需要符合任务权限或获得单独授权。
- 下载前再次检查权限、授权状态与有效期；撤销或到期后不再签发新下载凭证。
- 使用短期下载地址时，首版约定有效期不超过 5 分钟，且不晚于授权到期时间；撤销前已签发的地址可能在其有效期内继续使用。
- 已下载的本地文件无法收回。签发下载地址的记录不得表述为用户已成功下载。

## 6. 状态与一致性规则

| 状态维度 | 状态范围 | 规则 |
| --- | --- | --- |
| 任务 | 草稿、已分配、执行中、待验收、已完成 | 待验收时退回补充可回到执行中；已完成为终态，保留历史 |
| 文件处理 | 上传中、校验中、就绪、处理失败 | 只有校验完成并固定内容的就绪版本可登记摘要 |
| 人工复核 | 待复核、通过、退回 | 与文件版本绑定，并发复核不得静默覆盖已有结论 |
| 链上存证 | 待处理、已提交、已确认、结果待确认、明确失败 | 请求超时不等于失败，提交不等于有效确认 |
| 共享申请 | 待审批、已批准、已拒绝、已过期、已撤销 | 访问须同时满足授权版本、用户和时间范围 |

“正式成果可共享”为派生条件：文件就绪、人工复核通过、链上存证已确认。存证失败不应自动把人工复核结论改为退回。

可靠性要求：

- 证据编号和版本唯一；相同版本、相同摘要的重复登记应幂等返回已有结果，不同摘要应拒绝覆盖。
- 文件成功保存但业务记录未成功建立时，不得显示为入库成功；允许回收不再被业务引用的临时文件。
- 已生成的存证任务在投递失败或服务重启后应可继续处理，不能依赖一次请求或一次消息回调。
- 存证调用超时后优先确认原交易或同一证据版本的登记结果；无法确认时保持待确认，不直接宣告失败。
- 对明确失败保留原因，支持受控重试；恢复成功后更新状态并保留处理记录。

## 7. 核验与追溯的含义

平台核验文件字节的 SHA-256 与链上登记摘要是否一致，至少区分以下结果：

| 结果 | 含义 |
| --- | --- |
| 内容一致 | 实际读取文件计算出的摘要与已确认登记摘要相同 |
| 内容不一致 | 实际计算出的摘要与已确认登记摘要不同 |
| 尚未确认存证 | 尚无有效确认的登记结果，暂不能给出一致性结论 |
| 文件缺失或读取失败 | 无法取得待核验内容，不能判定是否发生内容变化 |
| 链查询失败或超时 | 无法取得可靠登记结果，允许稍后重试 |

支持核验已保存文件，也支持有权限的用户提交副本与指定版本比较。核验应记录证据版本、执行人、结果和核验时间。

链上只登记文件摘要及必要提交信息，不承诺保护全部业务元数据。任务、设备、地点、声称的采集时间、上传人、复核与共享记录属于平台追溯信息，不宣称全部获得链上证明。

摘要一致不能证明照片真实拍摄于现场，也不能自动证明采集时间或位置真实。链上使用机构应用身份时，提交主体是机构应用；个人操作由平台审计记录关联，不宣称最终用户逐笔独立签名。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 文件私有存储；登录、角色和资源权限均有效；普通用户不得修改机构身份或覆盖正式证据 |
| 可恢复性 | 重复请求、消息重复、临时链服务不可用和应用重启后，已接受的存证任务能够查询或恢复 |
| 可观察性 | 可查看业务状态、证据版本、交易编号、存证状态和失败原因；记录关键操作时间与主体 |
| 可复现性 | 提供环境版本、配置样例、初始化数据、启动步骤和模拟器使用说明 |
| 性能验证 | 支持 3～5 台模拟设备并行执行；记录环境、文件大小、并发量、接口延迟、上传耗时及存证有效确认延迟 |

性能结论以实际压测为准，不预设未经验证的高并发或链吞吐量指标。具体默认配置、表结构、接口和可靠投递方案在设计文档中确定。

## 9. 验收场景

| 编号 | 操作场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 两机构用户登录，未参与任务且未获授权的运营商用户访问委托方资料 | 不能通过列表、详情、下载或核验接口获取该资料 |
| AC-02 | 一个任务拆为多个子任务，由 3～5 台模拟设备分别上报 | 能汇总各子任务结果，显示缺失资料；重复上报不重复计数 |
| AC-03 | 设备离线后调整分配，旧设备恢复并提交迟到数据 | 在线状态正确；旧批次可追溯，迟到数据不覆盖新批次正式成果 |
| AC-04 | 上传中途断开，再查询进度并续传，重复调用完成接口 | 已完成分片可复用，最终只生成一个正式版本，摘要对应完整文件 |
| AC-05 | 资料被退回，提交更正版本并复核 | 两版文件及复核历史均保留，新版本需重新复核和存证 |
| AC-06 | 运营商登记摘要，委托方查询并尝试登记；重复登记同一版本 | 两机构可查到相同已确认摘要；委托方登记被拒绝；相同摘要不重复登记，不同摘要不能覆盖 |
| AC-07 | 对原始文件和修改一个字节的副本分别核验 | 分别得到一致和不一致结果，核验副本不修改正式文件 |
| AC-08 | 文件缺失、存证未确认或链查询失败时发起核验 | 返回对应状态，不误报内容不一致或已被篡改 |
| AC-09 | 申请共享，审批前、批准后、到期后和撤销后分别尝试下载 | 各阶段权限正确；未复核或未确认存证的版本不可批准为正式共享成果 |
| AC-10 | 先取得短期下载地址，再撤销授权 | 不再签发新地址；已有地址的剩余有效期符合约定，签发日志不误记为实际下载成功 |
| AC-11 | 模拟投递失败、重复投递、存证请求超时及应用重启 | 任务可恢复或保持待确认；最终业务结果不重复，可查看状态和原因 |
| AC-12 | 尝试完成缺少资料或存在未复核新版本的任务，再补齐资料、复核和存证 | 提前完成被拒绝，全部必交资料的当前执行批次最新版本满足条件后允许完成；完成后拒绝新增正式成果版本 |

## 10. 实施与交付约定

先验证 Java 能完成 Fabric 有效提交与跨机构查询，再实现“创建任务—上传一个文件—登记摘要—核验”的最小闭环。随后补齐多机执行、分片续传、版本、复核、共享及异常恢复；阶段划分不减少本需求中的最终验收范围。

最终交付包含可运行的后端、模拟无人机程序、两个组织的开发网络、初始化数据、接口调用示例、部署说明和上述验收记录。管理端以完成操作和展示结果为目标，不要求复杂地图或大屏。

需求范围调整应同步更新本文及对应验收场景；数据库设计、接口细节和开发任务分别由后续设计文档与任务清单承接。

# T029 全量业务演示

本演示把双机构协作、四台设备、人工换机、旧新文件版本、人工复核、精确共享和文件核验串成一条可重复运行的业务流程。正常状态由正式 HTTP 接口、Outbox、文件 Worker 和真实 Fabric 调用产生；演示不通过 SQL 写入“已完成”或“已确认”。

接口总目录及逐项请求见 [examples/README.md](../examples/README.md)，串联手动模板见 [t029.http](../examples/t029.http)。本文说明操作顺序和结果判读；实际运行编号、检查数量、账本交易和结论统一记录在 [验证记录](verification.md)。T029 的演示不代替 T030 的 AC-01～AC-12 最终验收或 T031 的性能测量。

## 1. 环境与原数据

在仓库根目录使用 JDK 21，确认 `java -version` 和 `mvn -version` 都指向同一 JDK。沿用原 `.env`、`.local/demo-credentials.json`、数据库、Garage 私有桶、RabbitMQ、Redis、Fabric 通道及已部署的 evidence 链码；首次安装按 [项目说明](../README.md)、[基础设施说明](../deploy/README.md) 和 [Fabric 说明](../deploy/fabric/README.md) 完成。已有环境不重新生成账号密码、删除卷或重建账本。

```bash
mvn -B -ntp -Dmaven.repo.local="$PWD/.local/m2" -f backend/pom.xml -P database-probe,fabric-probe clean verify
docker compose --env-file .env -f deploy/compose.yml up -d --wait --wait-timeout 240
python3 deploy/fabric/network.py up
python3 deploy/fabric/network.py verify
```

开始自动演示前停止普通项目后端及其他业务探针、消息消费者，保留基础设施运行。确认已有定版、Outbox 和存证工作已经收敛。独立消息拓扑不能隔离同一数据库中仍待处理的业务；不要同时运行多个自动演示、恢复探针或管理端后端。

本次新建的任务、设备、版本、文件和链记录会保留，供浏览器继续查看；原 M2 演示任务与版本保持原状态，不将它们用于本演示的复核、共享审批或正式完成。再次普通运行应创建另一组演示资料；检查已有资料使用复查入口。

## 2. 六个账号与变量来源

账号密码由本机 `.local/demo-credentials.json` 的 `passwords` 按用户名读取。不要把密码、JWT、设备令牌或下载 URL 填进受版本控制的 `.http` 文件、工作区设置、终端命令或截图。手动 HTTP 客户端使用本机私有环境配置；页面登录使用同一批现有账号。

| 账号 | 机构与角色 | 本流程职责 |
| --- | --- | --- |
| owner-admin | OrgA；OWNER_TASK_ADMIN、ORG_ADMIN | 创建任务、指定运营商、维护委托方成员、正式完成任务 |
| owner-reviewer | OrgA；OWNER_REVIEWER | 作为任务成员，对各固定版本独立提交复核结论 |
| owner-approver | OrgA；OWNER_DATA_APPROVER | 作为任务成员，批准、拒绝或撤销精确版本共享 |
| operator-admin | OrgB；OPERATOR_TASK_ADMIN、ORG_ADMIN | 注册设备、维护运营方成员、建立子任务和批次、人工换机、启动及提交验收 |
| operator-user | OrgB；OPERATOR_USER | 作为任务成员上传资料、登记版本异常、读取及核验成果 |
| operator-outsider | OrgB；OPERATOR_USER | 保持为任务非成员，演示授权前拒绝、获批后精确版本访问以及撤销后失权 |

ORG_ADMIN 本身不授予任务、复核或共享审批权限；所有任务操作仍需要对应业务角色及显式任务成员。脚本只登录原账号，不退出原账号、不修改原密码、角色或 tokenVersion；手动操作退出页面会按正常身份规则使该账号原版本令牌失效，不要同时保留其他依赖该令牌的演示。

| 变量 | 取得方式与用途 |
| --- | --- |
| 用户编号、机构、角色 | 登录后读取 `/users/me`；页面“当前账号”可复制用户编号，用于分配和成员维护 |
| taskId、requirementId、subtaskId | 任务创建和后续任务详情响应；资料项绑定所属子任务 |
| deviceId、deviceToken | 设备注册响应；令牌只返回一次，设备接口使用 X-Device-Id/X-Device-Token，与用户 Bearer 身份分开 |
| executionId、currentExecutionId | 分配设备/换机后的响应及执行历史；上传和进度必须指向正确批次 |
| expectedLockVersion | 每次写入前读取相应任务、子任务或授权的最新 lockVersion，不能跨操作复用旧锁号 |
| clientRequestId | 每次新上传、共享申请或人工重检使用新的 UUID；同一不确定请求重试沿用原编号及相同内容 |
| uploadId、versionId、evidenceId、versionNo | 上传会话及定版后的版本响应；版本号不等于当前批次归属 |
| grantId、requestedValidUntil、validUntil | 申请及审批响应；有效期是未来 UTC 时间，批准期限不得晚于申请期限 |
| traceId、confirmedTxId | HTTP 响应及实际存证状态；用于关联审计和首次有效链登记，不包含原交易字节 |

## 3. 自动生成并保留演示结果

```bash
python3 deploy/scripts/run-demo.py
```

脚本自行启动打包应用，使用随机本地 HTTP 端口和独立消息拓扑，启用真实数据库、存储、消息及 ledger 能力。设备报告由模拟请求发送，不控制实际飞行器。JWT 和新设备明文令牌只在本轮进程内存使用，不写入报告或命令行。

安全产物位于 `.local/full-demo/<runId>/`，目录权限 0700，报告及样例输入权限 0600。以命令输出和安全报告中的资源编号为准，不复制其他轮次的 taskId、executionId 或 versionId。结束前等待自己的消息拓扑排空，再停止本次应用并清理空拓扑；保留新业务数据、文件、链登记和追加审计，不清理演示成果。

| 产物 | 用途 |
| --- | --- |
| report.json | 本轮场景、HTTP 请求及安全检查结果，包含实际运行结论 |
| resources.json | 本轮任务、资料项、子任务、执行批次、上传、固定版本及授权编号 |
| inspection.json | 数据库关系、私有对象实际字节及双机构账本的只读核对 |
| rechecks/ | 同一运行后续复查的独立报告，不覆盖原始运行证据 |

同一条演示资料的复查入口为：

```bash
python3 deploy/scripts/run-demo.py --recheck .local/full-demo/<runId>
```

复查先用原账号登录并正常追加 AUTH_LOGIN 认证审计，之后只通过 GET、数据库 SELECT、对象读取及链查询核对已保留业务资源，不重新创建任务、上传、复核结论、共享申请、业务核验记录或链登记；它用于证明现有对象、业务关系与实际账本仍对应。若需要重新体验从创建到完成的写入流程，普通运行新一轮，不能修改旧运行报告来伪装重跑成功。共享期限按数据库当前时间自然经过；复查应按当前有效期判断授权，不把历史曾获批当作永久权限。

如果运行已经生成四个 CONFIRMED 且 APPROVED 的固定版本，但后续验收/共享/核验步骤中断，可执行：

```bash
python3 deploy/scripts/run-demo.py --resume .local/full-demo/<runId>
```

此入口只支持上述明确检查点：先读取四版的实际状态，再继续任务验收、精确授权和必要核验，不重做设备注册、上传或链登记。审批使用当前锁号，已有的相同核验结果会复用。未到达此检查点的失败保留报告与资源，不能通过此命令跳过前置业务。旧版授权已自然到期等情形也会按当前真实状态拒绝，不强改数据库。失败报告仍保留，续跑结果写入独立 `resumes/<runId>/`；源目录的 `latest-resume.json` 指向成功续跑。后续对源目录使用 `--recheck` 会读取该成功续跑的资源清单，原失败报告不会改成成功。

普通成功运行由 `.local/full-demo/latest.json` 指向；成功续跑时，该文件保留源 `runDirectory`，`resourceDirectory` 指向续跑资源目录，`report` 指向真正成功报告。多次运行会保留多组资料和授权，观察“只见 V2”时按本次 taskId 筛选，不应把其他演示任务中的合法授权误认为越权。

## 4. 页面和 HTTP 演示顺序

自动生成结束后，要使用浏览器或手动请求继续查看，启动普通后端：

```bash
python3 deploy/scripts/run-backend.py --ledger
```

浏览器打开 `http://127.0.0.1:8080/`。界面与后端同源，无需额外前端开发服务器；JWT 只在页面内存，刷新后重新登录。完整文件指纹需要支持 Web Crypto 的现代浏览器，本地 HTTP 使用 localhost/127.0.0.1，其他部署使用 HTTPS。

手动执行新业务时，按 [t029.http](../examples/t029.http) 的前置顺序和角色逐条操作。每次响应后更新本机变量；新定版和人工换机可能改变“当前成果”，下一步读取最新详情，不依赖之前页面上的锁号或状态。

| 步骤 | 页面操作或 HTTP 入口 | 应观察的业务关系 |
| --- | --- | --- |
| 创建和分配 | 委托方建立包含三项必交资料的任务，分配运营商管理员，加入委托方复核/审批成员 | DRAFT→ASSIGNED；分配及成员维护成功不代表任务已经启动 |
| 配置多机 | 运营商登记四台设备，建立三个子任务，绑定三项资料，为三个子任务分配初始设备，加入上传者后启动 | 三台执行、一台备用；任务 RUNNING，各子任务有独立 currentExecutionId |
| 多机上报 | 三台设备各自发送心跳、bootId/seq 和进度，读取任务进度及设备列表 | 当前执行分别累计单调进度；重复同一事件不重复累计；在线状态与成果状态分开显示 |
| 人工换机 | 选择一个子任务，用当前子任务锁号、备用设备及非空原因新建执行批次 | 旧批次 CLOSED，新批次 RUNNING，当前执行指针变化；执行历史保留前任、原因、人员和时间 |
| 旧批次迟到 | 旧设备继续向原 executionId 上报，随后读取新当前进度 | 迟到事件归旧批次，不能把旧进度写入新批次；不要将旧设备请求改用新 executionId |
| 首版复核和共享 | 在换机后的当前执行中生成首资料 V1，取得 CONFIRMED，由复核人 APPROVED，再批准 operator-outsider 对该 V1 的申请 | 非成员只能读取这个固定版本；知道其他 UUID 不授予父任务或其他资料权限 |
| 补交新版本 | 同一资料使用新请求编号、新会话上传不同内容形成 V2，读取新版本及原收件人的可见列表 | V2 最初重新 PENDING，不继承 V1 的结论；原收件人仍只能读 V1，V2 与父任务均为 403 |
| 其他资料与独立复核 | 对 V2 单独复核，另外两个子任务各提交一份资料并分别复核、等待真实存证 | 三项当前成果分别 APPROVED+CONFIRMED；本任务保留四个固定版本及各自链登记，异常和复核只绑定指定版本 |
| 实际核验 | 有权限用户核验 STORED、原样 COPY 及内容变化 COPY；按需签发并实际请求下载地址 | MATCH/MISMATCH 来自实际字节比较；COPY 不覆盖正式对象、不新建版本；签发和实际下载分开核对 |
| 提交和完成 | 运营商提交验收，委托方检查当前成果后正式完成 | 先 WAITING_ACCEPTANCE；全部当前必交最新版本 APPROVED+CONFIRMED，且无阻挡的当前 VERIFYING，才能 COMPLETED 并写入 completedAt |
| 完成后撤销旧版 | 审批人撤销 V1 精确授权；收件人重新读取和请求签发 | V1 重新 403，不能再签发新地址；已签发地址可能在原到期前仍有效，任务完成时间不被改写 |
| 独立共享新版 | 收件人单独申请 V2，申请 24 小时，审批人批准 12 小时；再次读取可见列表 | 收件人最终仅看见 V2；V1、其他资料及父任务仍受限。批准只适用于当前有效期，复查到期后应看到相应失权 |
| 查看追溯 | 有权限管理成员按 taskId 查询审计及版本关系 | 创建、换机、上传、复核、申请、审批、撤销和核验可关联到实际任务及固定版本，不以外部用户的授权代替审计权限 |

手动模板在 V1 授权有效时核验 V1，自动脚本在完成任务并批准 V2 后核验 V2；应选择与所核验版本对应的原样文件。脚本的一字节变更副本只用于摘要核验，不声称其 PNG 容器仍有效。

已完成任务用于历史读取、核验及权限管理，不能再新增上传、版本、异常、复核或换机。要演示退回重开或补交新内容，应在正式完成之前完成这些操作，或另建一轮任务。

本轮三个当前执行最终分别上报 100%，备用设备接替其中一个子任务；换机前旧批次进度仍保留在执行历史。任务完成依据资料和复核/存证条件，不根据百分比直接推断成果已合格。

## 5. 状态与失败结果判读

| 结果 | 含义与后续操作 |
| --- | --- |
| 上传完成接口 HTTP 202 / VERIFYING | 已接受后台定版请求；继续查询会话，得到 COMPLETED 和 versionId 后才有固定版本 |
| 存证 PENDING / SUBMITTED / UNKNOWN | 尚未取得明确有效结果；UNKNOWN 显示结果待确认，系统沿原交易继续检查，不能当作失败后另发一笔新交易 |
| CONFIRMED | 已取得对应固定版本的实际有效账本结果；继续核对 evidenceId、versionNo、SHA-256 及首次有效交易编号 |
| APPROVED / RETURNED | 此固定版本的人工结论，与链状态独立；旧版结论或授权不向新版传播 |
| 核验 MATCH / MISMATCH | 已实际执行核验，字节摘要一致或不同；MISMATCH 是 HTTP 200 下的业务结果，不是接口失败 |
| ANCHOR_UNCONFIRMED / FILE_READ_FAILED / CHAIN_QUERY_FAILED | 尚不能给出一致性结论；不能统一解释为文件被篡改 |
| 列表 200 空 / 详情 403 | 当前身份无可见资料或无资源权限；同机构、知道 UUID 或拥有 ORG_ADMIN 均不自动授予任务访问 |
| 401 | 登录失效、账号/密码或设备凭据不符；重新确认原身份，不通过修改业务数据绕过鉴权 |
| 409 | 锁号或幂等内容冲突；重新读取当前状态，核对输入后显式重试，不能自动覆盖已有结论 |
| 503 或处理超时 | 依赖或容量暂时不可用；保留原请求编号、会话和安全报告，先排查状态，不清库或强写成功 |

失败运行的报告和已经产生的业务记录、链登记及审计继续保留。通过明确的只读复查入口检查旧运行，符合四版检查点的失败才可用 --resume 继续；普通重新运行创建新一轮，不把它伪称原运行恢复。原设备令牌丢失后不能从服务端读回明文，也不能把原凭据替换成文档中的占位值。

## 6. 演示时如何说明后端能力

按“看见的业务结果→对应的后端机制”说明：成员和精确授权对应数据库当前身份及 SQL 分页前过滤；上传重试对应稳定请求编号、分片摘要、唯一约束和定版冻结；状态与消息一致对应本地事务加 Outbox、发布确认和持久消费幂等；链结果不明对应原交易检查点及恢复对账；换机对应批次历史、当前执行指针和迟到隔离；任务完成对应当前最新成果、复核及真实存证的联合条件。

四台设备通过 HTTP 模拟，未接入真实飞控或自动调度。文件 SHA-256 一致只能证明核验字节与登记版本一致，不能证明现场内容真实。Fabric 只承担固定版本摘要登记和查询；Java 承担任务、权限、文件、事务、消息、恢复和审计。开发后端持有两个机构的本地应用身份，本演示不代表生产机构运维隔离或性能指标已经验证。
